# LiquorERP — Bug & Issue Report

Generated by codebase audit. 22 issues across frontend and backend.

---

## CRITICAL

### BUG-01 — Missing Prisma relation: `StockMovement` → `User` ✅ FIXED
**File:** `apps/api/prisma/schema.prisma`  
Added `createdBy User @relation(fields: [createdById], references: [id])` to `StockMovement` and `stockMovements StockMovement[]` to `User`.  
**Requires:** `prisma db push` + `prisma generate` to apply schema changes to the DB.

---

### BUG-02 — `PurchaseOrdersController` has no `RolesGuard` ✅ FIXED
**File:** `apps/api/src/modules/purchase-orders/purchase-orders.controller.ts`  
Added `RolesGuard` to `@UseGuards` and `@Roles(Role.ADMIN, Role.MANAGER)` to `create`, `receive`, and `cancel` routes.

---

### BUG-03 — TOCTOU race condition: stock check and deduction not in the same transaction ✅ FIXED
**File:** `apps/api/src/modules/sales/sales.service.ts`  
Refactored `create()` to wrap sale creation + all stock deductions in a single `this.prisma.$transaction(async (tx) => { ... })`.

---

## HIGH

### BUG-04 — `SalesController`: void route has no `@Roles` guard ✅ FIXED
**File:** `apps/api/src/modules/sales/sales.controller.ts`  
Added `RolesGuard` to controller-level `@UseGuards` and `@Roles(Role.ADMIN, Role.MANAGER)` to the void route.

---

### BUG-05 — `ReportsController`: `dateFrom`/`dateTo` are unvalidated ✅ FIXED
**File:** `apps/api/src/modules/reports/reports.controller.ts`  
Created `apps/api/src/modules/reports/dto/report-query.dto.ts` with `ReportDateRangeDto` (`@IsDateString() @IsOptional()`) and `DeadStockQueryDto` (`@Type(() => Number)`). Controller and service updated to handle optional dates gracefully.

---

### BUG-06 — N+1 serial DB loops per sale item ✅ FIXED
**File:** `apps/api/src/modules/sales/sales.service.ts`  
Replaced serial per-item `findUnique` calls with a single `findMany({ where: { id: { in: ids } } })`. All stock updates run inside the single `$transaction` added for BUG-03.

---

### BUG-07 — `PurchaseOrdersService.receiveGoods` does not validate over-receiving ✅ FIXED
**File:** `apps/api/src/modules/purchase-orders/purchase-orders.service.ts`  
Added check: `if (poItem.receivedQty + item.receivedQty > poItem.orderedQty) throw new BadRequestException(...)`.

---

### BUG-08 — `register/page.tsx` uses wrong hardcoded port 3001 ✅ FIXED
**File:** `apps/web/src/app/(auth)/register/page.tsx`  
Replaced raw `fetch("http://localhost:3001/v1/users", ...)` with `import { api } from "@/lib/api"` and `api.post("/users", form)`.

---

### BUG-09 — Dead `apiClient` at wrong port ✅ FIXED
**File:** `apps/web/src/lib/api/client.ts`  
File deleted.

---

### BUG-10 — `PurchaseOrdersController.cancel` records no audit of who cancelled ✅ FIXED
**File:** `apps/api/src/modules/purchase-orders/purchase-orders.controller.ts`  
`cancel` route now injects `@CurrentUser("id") userId` and passes it to `poService.cancel(id, userId)`. Service signature updated to accept `userId`.

## MEDIUM

### BUG-11 — Unhandled promise rejection in `handleAdjust` ✅ FIXED
**File:** `apps/web/src/app/(dashboard)/inventory/page.tsx`  
Wrapped `adjustStock.mutateAsync(...)` in `try/catch` so API errors don't produce unhandled rejections.

---

### BUG-12 — `page` not reset when `typeFilter` changes on Inventory page ✅ FIXED
**File:** `apps/web/src/app/(dashboard)/inventory/page.tsx`  
`typeFilter` `onValueChange` handler now also calls `setTableParams(p => ({ ...p, page: 1 }))`.

---

### BUG-13 — `columns` `useMemo` lists `voidSale` as a dependency ✅ FIXED
**File:** `apps/web/src/app/(dashboard)/sales/page.tsx`  
Removed `voidSale` from the `useMemo` dependency array — it is not used inside column definitions.

---

### BUG-14 — `SalesPage` silently breaks if `/sales` API is ever paginated ✅ FIXED
**File:** `apps/web/src/app/(dashboard)/sales/page.tsx`  
Changed cast to `(salesData as any)?.data ?? (salesData as Sale[] | undefined) ?? []` to handle both array and paginated response shapes.

---

### BUG-15 — Dashboard pending PO count uses fragile `unknown[]` cast ✅ FIXED
**File:** `apps/web/src/components/modules/dashboard/dashboard-page.tsx`  
Replaced cast with helper `poLength(d)` that checks `d?.data?.length ?? d?.length ?? 0`, handling both array and paginated shapes.

---

### BUG-16 — `/register` page publicly accessible without auth ✅ FIXED
**File:** `apps/web/src/middleware.ts`  
Removed `/register` from `PUBLIC_PATHS`. Unauthenticated users are now redirected to `/login`.

---

### BUG-17 — COGS uses current `costPrice`, not historical cost ✅ FIXED
**Files:** `apps/api/prisma/schema.prisma`, `apps/api/src/modules/sales/sales.service.ts`, `apps/api/src/modules/reports/reports.service.ts`  
Added `costAtSale Decimal?` to `SaleItem`. Populated from `variant.costPrice` at sale creation time. `salesSummary` COGS now uses `i.costAtSale ?? i.variant.costPrice`.  
**Requires:** `prisma db push` + `prisma generate` to apply schema changes to the DB.

---

## LOW

### BUG-18 — Low-stock filter done in memory instead of DB ✅ FIXED
**Files:** `apps/api/src/modules/products/products.service.ts`, `apps/api/src/modules/reports/reports.service.ts`, `apps/api/src/modules/inventory/inventory.service.ts`  
All three functions now use `prisma.$queryRaw` with `WHERE current_stock <= reorder_point AND is_active = true` instead of loading the full table and filtering in JS.

---

### BUG-19 — Full variants array returned in stock summary ✅ FIXED
**File:** `apps/api/src/modules/inventory/inventory.service.ts`  
`getStockSummary` now returns only `{ totalVariants, totalValue, lowStockCount }` using aggregate SQL queries — no longer loads all variant rows into memory.

---

### BUG-20 — `now` not in `useMemo` deps in `StockMovementChart` ✅ FIXED
**File:** `apps/web/src/components/modules/dashboard/stock-chart.tsx`  
Moved `const now = new Date()` inside `useMemo` so day buckets recompute correctly if the component lives past midnight.

---

### BUG-21 — `isActive` Transform maps garbage input to `false` ✅ FIXED
**File:** `apps/api/src/modules/products/dto/product-query.dto.ts`  
Transform updated to `value === "true" ? true : value === "false" ? false : undefined` so invalid values are ignored rather than treated as `false`.

---

### BUG-22 — `quantity: 0` accepted in stock adjustment ✅ FIXED
**File:** `apps/api/src/modules/inventory/dto/stock-adjustment.dto.ts`  
Added `@NotEquals(0, { message: "Quantity cannot be zero" })` decorator.
